# 데이터베이스의 큰 그림

## 데이터베이스와 DBMS

### 데이터베이스의 정의

- **데이터베이스(Database)**는 구조화된 데이터를 저장하고 관리하기 위한 시스템이다.
    
- 다양한 응용 프로그램에서 데이터의 **중복 없이 효율적으로 접근**하고 **공유**할 수 있도록 설계됨.
    
- 예: 고객 정보, 주문 내역, 제품 데이터 등.
    

### DBMS의 정의

- **DBMS(Database Management System)**는 데이터베이스를 관리하는 소프트웨어.
    
- 사용자와 데이터베이스 사이에서 중재자 역할 수행.
    
- 데이터의 **정의(DDL)**, **조작(DML)**, **보안 및 무결성 유지**, **동시성 제어**, **백업 및 복구** 등을 담당함.
    

### DBMS의 종류

|분류 기준|종류 및 설명|
|---|---|
|**데이터 모델**|관계형(RDBMS: MySQL, PostgreSQL), NoSQL(MongoDB, Cassandra), 객체지향형 등|
|**용도/환경**|중앙 집중형, 분산형, 클라우드 기반 DBMS|

### 파일 대신 데이터베이스를 이용하는 이유

1. **데이터 일관성 및 무결성 제공 어려움**: 파일 시스템은 데이터의 제약 조건을 강제하기 어려움.
    
2. **불필요한 중복 저장**: 동일한 데이터를 여러 파일에 저장하게 되어 비효율 발생.
    
3. **데이터 변경 시 연관 데이터 변경이 어려움**: 파일 간의 관계를 명시적으로 표현하기 어려움.
    
4. **정교한 검색이 어려움**: 조건 검색, 다중 조건 검색이 비효율적.
    
5. **백업 및 복구가 어려움**: 파일 시스템은 자동 백업/복구 기능이 부족함.

## 데이터베이스의 저장 단위와 트랜잭션

### 데이터베이스의 저장 단위

- **엔티티(Entity)**: 독립적인 실체 (예: 사용자, 상품)
    
- **속성(Attribute)**: 엔티티가 가지는 속성값 (예: 이름, 가격)
    
- **엔티티 집합(Entity Set)**: 동일한 유형의 엔티티 모음
    
- **릴레이션(Relation)**: 관계형 데이터베이스에서 테이블과 같은 개념
    
- **레코드(Record)**: 릴레이션의 각 행 (튜플)
    
- **필드(Field)**: 릴레이션의 각 열 (속성)
    
- **차수(Degree)**: 릴레이션의 속성 개수
    
- **카디널리티(Cardinality)**: 릴레이션의 튜플 개수
    
- **도큐먼트(Document)**: MongoDB 등의 NoSQL에서 하나의 데이터 단위
    
- **컬렉션(Collection)**: NoSQL에서 도큐먼트들의 집합
    

### 스키마(Schema)

- 데이터베이스의 **구조와 제약조건을 정의**한 것
    
- 테이블, 필드, 자료형, 관계 등을 설계한 뼈대
    
- **스키마-리스(Schema-less)** 데이터베이스는 NoSQL에서 흔하며, 구조가 유연하고 변화에 민감하게 대응 가능
    

### 트랜잭션과 ACID

#### 트랜잭션(Transaction)

- **데이터베이스의 상태를 변화시키는 작업의 단위**
    
- 예: 계좌 이체 → 출금 + 입금
    

#### 초당 트랜잭션 (TPS: Transactions Per Second)

- DBMS의 성능 지표 중 하나. 초당 몇 개의 트랜잭션을 처리할 수 있는지 나타냄.
    

#### ACID 특성

| 특성                    | 설명                                             |
| --------------------- | ---------------------------------------------- |
| **원자성 (Atomicity)**   | 모든 작업이 전부 수행되거나 전혀 수행되지 않아야 함 (All or Nothing) |
| **일관성 (Consistency)** | 트랜잭션 전후에 데이터베이스의 무결성이 유지됨                      |
| **격리성 (Isolation)**   | 동시에 실행되는 트랜잭션은 서로 간섭하지 않음                      |
| **지속성 (Durability)**  | 트랜잭션 완료 후 데이터는 영구적으로 저장됨                       |

#### 커밋(Commit)과 롤백(Rollback)

- **커밋**: 트랜잭션에서 변경한 내용을 데이터베이스에 영구 반영
    
- **롤백**: 트랜잭션 중 오류 발생 시, 변경된 내용을 모두 취소하고 이전 상태로 복원

## RDBMS의 기본

### 테이블의 구성: 필드와 레코드

#### 필드타입

- **필드타입의 개념**: 테이블의 각 필드는 특정한 데이터 형식을 가짐
    
- **숫자형**: INT, FLOAT, DOUBLE 등 숫자 저장
    
- **문자형**: CHAR, VARCHAR 등 문자열 저장
    
- **날짜/시간형**: DATE, TIME, DATETIME 등
    
- **기타**: BLOB(이진 데이터), ENUM(열거형) 등
    

#### 키

- **키의 개념**: 테이블에서 각 레코드를 고유하게 식별하거나 관계를 맺기 위한 속성
    
- **후보키(Candidate Key)**: 유일하게 식별 가능한 모든 키
    
- **기본키(Primary Key)**: 후보키 중 선택된 대표 키, NULL 불가, 중복 불가
    
- **대체키(Alternate Key)**: 기본키로 선택되지 않은 후보키
    
- **슈퍼키(Super Key)**: 유일성을 만족하는 속성의 집합
    
- **복합키(Composite Key)**: 둘 이상의 속성으로 구성된 키
    
- **외래키(Foreign Key)**: 다른 테이블의 기본키를 참조하는 키
    

### 테이블의 관계

#### 일대일(1:1) 대응관계

- 하나의 레코드가 다른 테이블의 하나의 레코드와만 연결됨
    
- 예: 주민등록번호 ↔ 주민정보
    

#### 일대다(1:N) 대응관계

- 하나의 레코드가 여러 레코드와 연결됨
    
- 예: 고객 ↔ 주문(한 고객은 여러 주문 가능)
    

#### 다대다(N:M) 대응관계

- 여러 레코드가 서로 여러 레코드와 연결됨
    
- 예: 학생 ↔ 강의(학생은 여러 강의 수강, 강의는 여러 학생 포함)
    
- 보통 **중간 테이블**(예: 수강 테이블)을 사용하여 구현
    

### 무결성 제약 조건

- **무결성 제약조건의 개념**: 데이터의 정확성과 일관성을 보장하기 위한 제약
    

#### 도메인 제약조건

- 각 속성값은 정의된 도메인(자료형, 범위)을 따라야 함
    

#### 원자값 개념

- 각 필드는 **더 이상 나눌 수 없는 원자값**만 저장해야 함 (정규화 개념과 연결)
    

#### 키 제약조건

- 기본키는 반드시 유일하고 NULL이 될 수 없음
    

#### 엔티티 무결성 제약조건

- 기본키는 반드시 값을 가져야 하며 NULL을 허용하지 않음
    

#### 참조 무결성 제약조건

- 외래키는 참조하는 테이블의 기본키 값과 일치해야 함
    
- 참조 대상이 삭제/수정될 경우 처리는 다음과 같음:
    
    - **연산 제한(RESTRICT/NO ACTION)**: 참조 중인 데이터가 있으면 삭제/수정 불가
        
    - **기본값 설정(SET DEFAULT)**: 외래키를 기본값으로 변경
        
    - **NULL 값 설정(SET NULL)**: 외래키를 NULL로 변경
        
    - **연쇄 변경(CASCADE)**: 외래키도 같이 변경/삭제됨

## SQL

### 데이터 정의 언어 (DDL: Data Definition Language)

- **테이블, 뷰, 인덱스, 제약 조건** 등을 정의하거나 변경, 삭제하는 명령어
    

#### CREATE 문

```
CREATE TABLE 테이블명 (
  열1 데이터타입 [제약조건],
  열2 데이터타입 [제약조건],
  ...
);
```

**제약조건 종류**

|제약조건|설명|
|---|---|
|PRIMARY KEY|기본키, 유일 + NOT NULL|
|FOREIGN KEY|외래키, 참조 무결성 유지|
|UNIQUE|중복 금지|
|NOT NULL|NULL 허용 안 함|
|DEFAULT|기본값 설정|
|CHECK|조건 만족 시 입력 허용|

#### ALTER 문

```
ALTER TABLE 테이블명 ADD 열명 데이터타입;
ALTER TABLE 테이블명 MODIFY 열명 데이터타입;
ALTER TABLE 테이블명 DROP COLUMN 열명;
```

#### DROP 문

```
DROP TABLE 테이블명;
```

- 테이블 구조와 데이터 완전 삭제
    

#### TRUNCATE 문

```
TRUNCATE TABLE 테이블명;
```

- 테이블 구조는 남기고 데이터만 삭제
    

**DROP vs TRUNCATE**

|   |   |   |
|---|---|---|
|항목|DROP|TRUNCATE|
|데이터 삭제|O|O|
|테이블 구조 삭제|O|X|
|롤백 가능 여부|X|X (일부 DBMS 지원)|
|트리거 작동 여부|O|X (대부분 무시됨)|

### 데이터 조작 언어 (DML: Data Manipulation Language)

#### SELECT 문

```
SELECT 열1, 열2 FROM 테이블명 WHERE 조건;
```

- **패턴 검색**: `LIKE`, `IN`, `BETWEEN`, `IS NULL`
    
- **연산자**: `+`, `-`, `*`, `/`, `%`, `AND`, `OR`, `NOT`
    
- **집계 함수**: `COUNT()`, `SUM()`, `AVG()`, `MAX()`, `MIN()`
    

#### INSERT 문

```
INSERT INTO 테이블명 (열1, 열2) VALUES (값1, 값2);
```

#### UPDATE 문

```
UPDATE 테이블명 SET 열1=값1, 열2=값2 WHERE 조건;
```

- 외래키 제약조건 위반 시 오류 발생 가능
    

#### DELETE 문

```
DELETE FROM 테이블명 WHERE 조건;
```

- WHERE 없이 실행 시 전체 삭제 (주의!)
    

---

### GROUP BY

```
SELECT 열, 집계함수 FROM 테이블명 GROUP BY 열;
```

- 같은 값을 가진 행들을 그룹화하여 집계
    

### HAVING

```
SELECT 열, 집계함수 FROM 테이블명 GROUP BY 열 HAVING 조건;
```

- GROUP BY 결과에 조건 걸기 (WHERE과 구분)
    

### ORDER BY

```
SELECT * FROM 테이블명 ORDER BY 열 ASC|DESC;
```

- 결과 정렬 (기본: ASC)
    

### LIMIT

```
SELECT * FROM 테이블명 LIMIT 숫자 OFFSET 시작번호;
```

- 출력할 행 수 제한 (MySQL 등에서 사용)
    

---

### 트랜잭션 제어 언어 (TCL: Transaction Control Language)

|   |   |
|---|---|
|명령어|설명|
|COMMIT|트랜잭션의 변경 사항을 확정하여 저장|
|ROLLBACK|트랜잭션의 변경 사항을 취소하고 이전 상태로 복원|
|SAVEPOINT|중간 저장 지점을 설정하여 일부만 ROLLBACK 가능|

```
BEGIN;
UPDATE 계좌 SET 잔액 = 잔액 - 10000 WHERE 사용자 = 'A';
SAVEPOINT A;
UPDATE 계좌 SET 잔액 = 잔액 + 10000 WHERE 사용자 = 'B';
-- 오류 발생 시
ROLLBACK TO A;
COMMIT;
```

**자동 커밋 (Auto Commit)**

- SQL 명령어 실행 시 즉시 커밋되는 기능
    
- 기본적으로 DDL은 자동 커밋됨

### 데이터 제어 언어 (DCL: Data Control Language)

#### GRANT

```
GRANT 권한 ON 테이블명 TO 사용자;
```

- 예: `GRANT SELECT, INSERT ON student TO user1;`
    

#### REVOKE

```
REVOKE 권한 ON 테이블명 FROM 사용자;
```

- 예: `REVOKE SELECT, INSERT ON student FROM user1;`

## 효율적 쿼리

### 서브쿼리와 조인

#### 서브쿼리 (Subquery)

- **개념**: 쿼리 내에 포함된 또 다른 SELECT 문
    
- 주로 WHERE, FROM, SELECT 절에서 사용
    

```
SELECT 이름 FROM 학생 WHERE 학번 IN (SELECT 학번 FROM 수강 WHERE 과목 = 'DB');
```

#### 조인 (Join)

- **개념**: 두 개 이상의 테이블을 연결하여 데이터를 조회
    

|유형|설명|
|---|---|
|INNER JOIN|두 테이블 모두에 공통된 데이터만 조회|
|LEFT OUTER JOIN|왼쪽 테이블은 모두 출력, 오른쪽 테이블은 매칭되는 데이터만 출력|
|RIGHT OUTER JOIN|오른쪽 테이블은 모두 출력, 왼쪽 테이블은 매칭되는 데이터만 출력|
|FULL OUTER JOIN|양쪽 테이블의 모든 데이터를 출력 (미지원 DB도 있음)|

```
SELECT * FROM 학생 INNER JOIN 수강 ON 학생.학번 = 수강.학번;
```

#### UNION

- 두 SELECT 결과를 합침 (중복 제거)
    
- `UNION ALL`은 중복 제거하지 않음
    

```
SELECT 이름 FROM 학생
UNION
SELECT 이름 FROM 교수;
```

---

### 뷰 (View)

- **개념**: SELECT 문을 저장한 가상의 테이블
    
- 보안, 재사용, 복잡한 쿼리 단순화 목적
    

```
CREATE VIEW student_view AS
SELECT 이름, 학번 FROM 학생 WHERE 학과 = '컴퓨터공학';

DROP VIEW student_view;
```

---

### 인덱스 (Index)

- **검색 속도 향상을 위한 데이터 구조**
    

|   |   |
|---|---|
|유형|설명|
|클러스터형 인덱스 (Clustered)|실제 데이터가 인덱스 정렬 순서대로 저장됨 (테이블당 하나)|
|논클러스터형 인덱스 (Non-Clustered)|인덱스만 정렬되어 있고 실제 데이터는 따로 저장됨|
|세컨더리 인덱스|기본 키 외의 다른 열에 대해 추가로 설정하는 인덱스|

```
CREATE INDEX idx_name ON 학생(이름);
```

## 데이터베이스 설계

### ER 다이어그램 (ERD: Entity-Relationship Diagram)

- **ERD 개념**: 엔티티(개체), 속성, 관계를 도식적으로 표현한 데이터 모델 설계 도구
    

#### 표기법 종류

|표기법|설명|
|---|---|
|피터첸|관계를 다이아몬드로, 엔티티를 사각형으로 표현|
|IE (Information Engineering)|관계를 선과 기호로 표현, Crow's Foot 방식 포함|
|새발, 까마귀발 (Crow's Foot)|관계 다중성을 선 끝의 모양으로 표현 (1:1, 1:N, N:M 등)|

#### 식별/비식별 관계

- **식별 관계**: 자식 테이블의 기본키에 부모의 기본키가 포함됨 (PK + FK)
    
- **비식별 관계**: 자식 테이블의 외래키는 PK에 포함되지 않음 (단순 FK)
    

---

### 정규화 (Normalization)

- **정규화 개념**: 데이터 중복 제거 및 이상 현상 방지를 위해 테이블을 구조화하는 과정
    

#### 제1정규형 (1NF)

- 모든 속성의 값은 **원자값(Atomic Value)**이어야 함
    
- 반복 속성 제거
    

#### 제2정규형 (2NF)

- **1NF 만족** + **부분 함수 종속 제거** (기본키의 일부에만 종속된 속성 제거)
    

#### 제3정규형 (3NF)

- **2NF 만족** + **이행적 함수 종속 제거** (A→B, B→C이면 A→C 되는 경우 제거)
    

#### 보이스-코드 정규형 (BCNF)

- **모든 결정자가 후보키**여야 함
    
- 3NF보다 엄격한 조건
    

#### 제4정규형 (4NF)

- 다치 종속(Multi-valued Dependency) 제거
    
- 하나의 속성이 두 개 이상의 독립적인 다중값을 가지는 경우 분해
    

#### 제5정규형 (5NF)

- 조인 종속(Join Dependency) 제거
    
- 분해된 릴레이션을 조인했을 때 원래 릴레이션이 아닌 경우 처리
    

#### 역정규화 (Denormalization)

- 성능 향상을 위해 정규화된 테이블을 다시 통합하거나 중복 허용
    
- 읽기 성능은 증가하지만 중복 및 무결성 문제 가능성 있음

## NoSQL

### NoSQL의 특징

- 전통적인 관계형 데이터베이스(RDBMS)의 한계를 보완하기 위해 등장
    
- **스키마 유연성**, **수평적 확장성**, **고속 읽기/쓰기 성능**이 강점
    
- 대용량 데이터 처리에 적합
    

#### 키-값(Key-Value) 데이터베이스

- **개념**: 고유한 키에 데이터를 값으로 저장하는 방식
    
- **장점**: 매우 빠른 읽기/쓰기, 단순한 구조
    
- **예**: Redis, DynamoDB
    

**인메모리 데이터베이스**

- 데이터를 디스크가 아닌 메모리에 저장하여 빠른 처리 속도 제공
    
- 예: Redis
    

#### 도큐먼트(Document) 데이터베이스

- **개념**: JSON, BSON, XML 형식의 도큐먼트를 저장하고 관리하는 DB
    
- **유연한 스키마**를 가짐
    
- **컬렉션(Collection)**: 도큐먼트들을 모은 논리적 단위
    
- 예: MongoDB
    

#### 그래프(Graph) 데이터베이스

- **개념**: 노드(개체)와 간선(관계)으로 데이터를 표현
    
- 복잡한 관계 탐색에 유리 (예: 소셜 네트워크)
    
- 예: Neo4j, Amazon Neptune
    

#### 칼럼 패밀리(Column Family) 데이터베이스

- **개념**: 행-열 구조의 확장 형태로, 컬럼들을 그룹으로 묶어 저장
    
- **칼럼 패밀리**: 관련된 컬럼들의 집합
    
- **키스페이스(Keyspace)**: 논리적 데이터베이스 단위
    
- 예: Apache Cassandra, HBase

### MongoDB와 Redis

#### MongoDB의 대표적인 연산자

- `$gt`, `$lt`, `$eq`, `$ne`, `$in`, `$nin`: 비교 연산자
    
- `$and`, `$or`, `$not`, `$nor`: 논리 연산자
    
- `$exists`, `$type`, `$regex`: 조건 연산자
    
- `$set`, `$unset`, `$inc`: 갱신 연산자
    

```
// 예: 나이가 20 이상인 사용자 조회
{ age: { $gte: 20 } }
```

#### Redis의 대표적인 명령어

- `SET key value`: 키-값 설정
    
- `GET key`: 값 조회
    
- `DEL key`: 키 삭제
    
- `EXPIRE key seconds`: TTL 설정
    
- `INCR key`, `DECR key`: 숫자 증가/감소
    
- `LPUSH list value`, `RPUSH list value`: 리스트 삽입
    
- `HSET hash field value`, `HGET hash field`: 해시 자료형

```
SET name "Alice"
GET name
```
